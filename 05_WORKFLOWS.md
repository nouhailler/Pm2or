# PM² Desktop — Workflows V0.1

## Project lifecycle
DRAFT → LAUNCH → PLANNING → EXECUTION → CLOSING → CLOSED

## RfP
LAUNCH → RFP_REVIEW → APPROVED/REJECTED/APPROVED_WITH_RESERVES → PLANNING

RfP checklist is data-driven from methodology configuration.

## RfE
PLANNING → RFE_REVIEW → APPROVED/REJECTED/APPROVED_WITH_RESERVES → EXECUTION

Minimum checks:
- Charter approved
- governance assigned
- stakeholders identified
- Work Plan sufficiently complete
- budget established
- risks assessed
- requirements plan available
- quality approach available
- communication approach available
- acceptance approach available
- transition/implementation plans where applicable
- deliverables identified
- acceptance criteria identified

## RfC
EXECUTION → RFC_REVIEW → APPROVED/REJECTED/APPROVED_WITH_RESERVES → CLOSING

Minimum checks:
- deliverables accepted or dispositioned
- open critical issues resolved or formally transferred
- required changes closed
- transition completed or transferred
- final reporting ready
- lessons learned collected
- closure actions assigned

## Risk
OPEN → ASSESSED → RESPONSE_PLANNED → MONITORED → CLOSED

## Issue
OPEN → ANALYSIS → ACTION_PLANNED → IN_PROGRESS → RESOLVED → CLOSED

## Decision
OPEN → ANALYSIS → DECIDED → COMMUNICATED → CLOSED

## Change
DRAFT → SUBMITTED → IMPACT_ANALYSIS → APPROVAL → APPROVED/REJECTED → IMPLEMENTING → VERIFIED → CLOSED

## Requirement
DRAFT → REVIEW → APPROVED → IMPLEMENTED → VERIFIED → ACCEPTED

## Deliverable
PLANNED → IN_PROGRESS → READY_FOR_ACCEPTANCE → ACCEPTED/REJECTED → CLOSED

## Document
DRAFT → IN_REVIEW → APPROVED → BASELINED → SUPERSEDED

## Meetings
PLANNED → HELD → MINUTES_DRAFT → MINUTES_APPROVED → CLOSED

Every workflow transition must be validated by the application service layer, not only by the UI.
