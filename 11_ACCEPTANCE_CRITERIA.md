# PM² Desktop — Acceptance Criteria V0.1

## AC-01 Project
User can create, save, reopen and archive a PM² project locally.

## AC-02 Lifecycle
Project can move through Launch, Planning, Execution and Closing using controlled transitions.

## AC-03 Gates
RfP, RfE and RfC exist as explicit reviews with configurable checklists and decisions.

## AC-04 Governance
User can assign PM² roles to persons and maintain project governance.

## AC-05 RCmSCI
User can maintain R/Cm/S/C/I assignments and the system blocks duplicate R or Cm assignments for one subject.

## AC-06 Work Plan
User can create hierarchical WBS, tasks, milestones, dependencies, dates, effort, cost and progress.

## AC-07 Requirements
User can create requirements and link them to tasks, deliverables and verification/acceptance tests.

## AC-08 Deliverables
User can manage deliverables and acceptance criteria/status.

## AC-09 Registers
Four PM² registers are fully operational: Risks, Issues, Decisions, Changes.

## AC-10 Traceability
User can navigate from an entity to related entities and see relation type.

## AC-11 Validation
Dashboard and entity views display PM² consistency warnings/errors.

## AC-12 Documents
User can generate core PM² artifacts from structured project data.

## AC-13 Export
User can export Markdown, HTML, DOCX, PDF and .pm2.

## AC-14 Offline
Application works without Internet access after installation.

## AC-15 Data safety
Save/reopen preserves all project data. Corrupt archive produces a clear error without silently overwriting data.

## AC-16 Audit
Important workflow transitions and approvals create audit entries.

## AC-17 Usability
A user can create a minimal project and reach RfP without editing raw JSON/YAML.

## AC-18 Extensibility
PM² lifecycle, roles, artifacts, gates and validation configuration are separated from UI code.
